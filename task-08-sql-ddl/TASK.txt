==============================================================================
TASK 08 - DDL & CONSTRAINTS (CREATE TABLE, ALTER TABLE)
==============================================================================

OBJECTIVE
------------------------------------------------------------------------------
Extend the Pizza Flight database schema using Data Definition Language (DDL)
statements and enforce data integrity with constraints (PRIMARY KEY,
FOREIGN KEY, NOT NULL, UNIQUE, CHECK, DEFAULT).

IMPORTANT TIP:
Reset your database with database/schema_and_seed.sql before testing
solutions.sql. Do NOT commit changes to database/pizza_flight.mv.db!


SCENARIO
------------------------------------------------------------------------------
Pizza Flight wants to track technician maintenance logs for its vending
machines and also add a discount voucher system.


EXERCISES
------------------------------------------------------------------------------
Write the SQL statements for each of the following 6 tasks in solutions.sql:

1. Create a "maintenance_logs" table (CREATE TABLE):
   Create a table named maintenance_logs with these columns and constraints:
     - log_id            : INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
     - machine_id        : INT NOT NULL, FOREIGN KEY referencing
                           machines(machine_id)
     - technician_name   : VARCHAR(80) NOT NULL
     - service_date      : DATE NOT NULL
     - issue_description : VARCHAR(255) NOT NULL
     - cost              : DECIMAL(7,2) NOT NULL DEFAULT 0.00,
                           CHECK (cost >= 0)
     - resolved          : BOOLEAN NOT NULL DEFAULT FALSE

2. Insert valid test data into "maintenance_logs" (INSERT):
   Insert 2 rows into maintenance_logs:
     - Machine 4 (PF-MUC-01), technician 'Tim Berger',
       service_date DATE '2026-03-12',
       issue_description 'Oven temperature sensor replaced',
       cost 145.50, resolved TRUE
     - Machine 6 (PF-FRA-01), technician 'Sara Klein',
       service_date DATE '2026-03-14',
       issue_description 'Payment terminal offline',
       cost 0.00, resolved FALSE

3. Verify constraints (leave commented out in solutions.sql!):
   Try running an INSERT with a negative cost (e.g., -10.00) or a
   non-existent machine_id (e.g., 999) in DBeaver to see H2 reject it!
   Write ONE invalid INSERT example as a SQL comment ("-- ...") in
   solutions.sql and briefly explain in a comment which constraint rejects it.

4. Create a "vouchers" table (CREATE TABLE with UNIQUE & CHECK):
   Create a table named vouchers with:
     - voucher_id       : INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
     - voucher_code     : VARCHAR(20) NOT NULL UNIQUE
     - discount_percent : INT NOT NULL CHECK (discount_percent BETWEEN 5 AND 50)
     - valid_until      : DATE NOT NULL
     - is_active        : BOOLEAN NOT NULL DEFAULT TRUE

5. Modify an existing table (ALTER TABLE):
   Add a new nullable column "phone_number VARCHAR(30)" to the "customers"
   table, and then update customer 1 (Lukas Meyer) with the phone number
   '+49 30 1234567'.

6. Query your new table (SELECT + JOIN):
   Write a SELECT query that joins maintenance_logs with machines to display:
   code, city, technician_name, service_date, cost, resolved.
