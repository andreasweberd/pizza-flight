TASK 02 - ENTITY-RELATIONSHIP MODEL (ERM) IN CHEN NOTATION
==============================================================================

OBJECTIVE
------------------------------------------------------------------------------
Analyze the Pizza Flight business requirements below and design a complete
Entity-Relationship Model (ERM) using CHEN NOTATION.

REMINDER: Do NOT look inside the database/ folder yet! Design the model
purely from the specification below.


BUSINESS REQUIREMENTS
------------------------------------------------------------------------------
Pizza Flight operates a network of automated pizza vending machines across
multiple cities. The company needs a database to store and manage the
following information:

1. Vending Machines
   - Each vending machine has a unique machine ID, a unique machine code
     (e.g., PF-BER-01), the city it is located in, a location name
     (e.g., Central Station North), a current status (ACTIVE, MAINTENANCE,
     or OFFLINE), and an installation date.

2. Pizzas
   - Pizza Flight offers a standardized menu of pizzas. Each pizza has a
     unique pizza ID, a unique name (e.g., Margherita), a category
     (Classic, Meat, Vegetarian, Special), a base price, a baking time in
     seconds, whether it is vegetarian, and its calories.

3. Toppings
   - Each topping has a unique topping ID, a unique name (e.g., Mushrooms,
     Jalapenos), an extra price, and whether it is vegan.
   - Every pizza has zero, one, or many default toppings, and each topping
     can be used on zero, one, or many pizzas.

4. Machine Inventory (Stock)
   - Each vending machine holds a certain stock of pizzas.
   - A vending machine can stock many pizzas, and the same pizza type can be
     stocked in many vending machines.
   - For each machine-pizza combination, we must record the current quantity
     in stock and the last restocked date.

5. Customers (Loyalty App Users)
   - Customers may optionally register in the Pizza Flight loyalty app.
   - Each registered customer has a unique customer ID, first name, last name,
     unique email, city, loyalty points, and a registration date.

6. Orders
   - When someone buys pizza at a machine, an order is recorded with a
     unique order ID, an order timestamp, a payment method (CARD, APP, or
     CASH), a total price, and an order status (COMPLETED or CANCELLED).
   - Every order is placed at exactly one vending machine, while a vending
     machine can have zero or many orders.
   - An order may be placed by at most one registered customer (walk-up
     guests order without an account!), and a registered customer can place
     zero or many orders.
   - Each order contains one or many pizzas, and each pizza can appear in
     zero or many orders. For each pizza in an order, we record the quantity
     ordered and the unit price at the time of purchase.
   - NOTE: Because a vending machine typically dispenses one pizza at a time,
     it is ALSO completely legal to model Order <-> Pizza as a 1:N
     relationship (one pizza per order) instead of N:M (multiple pizzas per
     order). Both 1:N and N:M are accepted!


REQUIRED NOTATION: CHEN NOTATION
------------------------------------------------------------------------------
Your diagram MUST follow Chen notation:

  - Rectangles    : Entity Types (e.g., Machine, Pizza, Topping, Customer,
                    Order)
  - Ovals         : Attributes, connected to their entity (or relationship)
                    * UNDERLINE every Primary Key attribute
  - Diamonds      : Relationships (use clear verb phrases, e.g., stocks,
                    places, contains, has)
                    * Attach relationship attributes (quantity,
                      last_restocked, unit_price) to the relationship diamond
  - Cardinalities : Clearly written on every relationship (e.g., 1:N, M:N or
                    (min,max) notation - be consistent throughout)
